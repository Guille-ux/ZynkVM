# ZynkVM Assembler and Bytecode Documentation

*Note: Comments in this documentation are for clarity only; the assembler itself does not support comments.*

---

## Introduction

**ZynkVM** is a modular and portable virtual machine that executes a compact bytecode format.  
The codebase is organized in a modern, maintainable way:  
- **Header files (`.h`)** contain only type definitions, macros, and function declarations (prototypes).  
- **Source files (`.c`)** contain all function implementations.  
- Only very small `static inline` functions are defined in headers.

---

## Project Structure and Code Organization

- **Directory structure** is organized by responsibility:
    - `core/` — VM, bytecode, and runtime logic
    - `core/types/` — Value and object types
    - `assembler/` — Assembler logic
    - `common/`, `utils/`, `ext/` — Shared utilities and platform abstractions

Example:
```
src/
  core/
    vm.h, vm.c
    chunk.h, chunk.c
    debug.h, debug.c
    opcodes.h
    hash.h, hash.c
    map.h, map.c
    types/
      value.h, value.c
      object.h
  assembler/
    zasm.h, zasm.c
    zcommon.h
  common/
    common.h
  utils/
    types.h
    tmem.h
```

**Key rules:**
- Use `#ifndef ... #define ... #endif` include guards in every header.
- Only include what you need in each header.
- Use `typedef struct ...;` for forward declarations to avoid circular dependencies.
- Implement all non-trivial functions in `.c` files, not in headers.
- Only very small `static inline` functions (like type checks) are defined in headers.

## Bytecode Format

**ZynkVM** bytecode consists of a sequence of instructions, where each instruction may include:
1. **Opcode**: A 1-byte unique identifier representing the operation to perform.
2. **Operands**: Optional data, such as constants or indices.

**General Structure:**
- `[Opcode] [Operand1] [Operand2] ...`

---

## Instruction Set

Below is a list of instructions supported by **ZynkVM**:

- **OP_CONSTANT (0x00)**: Pushes a constant from the constant pool onto the stack.  
  Operands: Index (4 bytes).
- **OP_RETURN (0x01)**: Ends execution and returns the value at the top of the stack.  
  Operands: None.
- **OP_NEGATE (0x02)**: Negates the value at the top of the stack.  
  Operands: None.
- **OP_ADD (0x03)**: Adds the top two values on the stack and pushes the result.  
  Operands: None.
- **OP_SUBSTRACT (0x04)**: Subtracts the top two values on the stack and pushes the result.  
  Operands: None.
- **OP_MULTIPLY (0x05)**: Multiplies the top two values on the stack and pushes the result.  
  Operands: None.
- **OP_DIVIDE (0x06)**: Divides the top two values on the stack and pushes the result.  
  Operands: None.

*(See `opcodes.h` for the full list.)*

## Bytecode Example

The following example demonstrates a program that adds two constants and returns the result:

**Assembler Code:**
```
CONSTANT;
3.14;
CONSTANT;
2.71;
ADD;
RETURN;
```

**Generated Bytecode:**
```
0x00 0x00 0x00 0x00 0x00  // OP_CONSTANT (index 0)
0x00 0x00 0x00 0x00 0x01  // OP_CONSTANT (index 1)
0x03                      // OP_ADD
0x01                      // OP_RETURN
```

## Assembler Format

The assembler uses a simple syntax based on line-separated instructions. Each instruction may include an opcode and, optionally, operands.

**Assembler Rules:**
1. Each instruction must end with a semicolon (`;`).
2. Operands (if any) must be separated by spaces.
3. Constant values are defined as decimal numbers.

**Example:**
```
CONSTANT;
42.0;
NEGATE;
RETURN;
```

## Extending the Bytecode

To add new instructions to the bytecode:
1. Define a new opcode in the `opcodes.h` file.
2. Implement the instruction logic in the `run` function in vm.c.
3. Update the assembler logic in zasm.c to translate the new instruction.

**Example: Adding a New Instruction `OP_PRINT`**
1. **Define the Opcode:**  
   Add to `opcodes.h`:
   ```
   OP_PRINT, // Prints the value at the top of the stack
   ```
2. **Implement the Logic:**  
   In `run` (in vm.c):
   ```
   case OP_PRINT:
       printVal(pop(vm));
       break;
   ```
3. **Update the Assembler:**  
   In zasm.c:
   ```
   else if (zcmp(line, "PRINT;", ';')) {
       code[*code_index] = OP_PRINT;
   }
   ```

## Testing

**Execution Test:**
1. Write a program in assembler.
2. Compile it into bytecode using the assembler.
3. Run the bytecode in ZynkVM and verify the results.

**Example:**
Assembler Input:
```
CONSTANT;
10;
CONSTANT;
20;
ADD;
PRINT;
RETURN;
```
Expected Output:
```
30
```
